# 持仓产品搜索与概览中文化设计

## 目标

除银行理财外，所有资产都必须先从公开数据源搜索并选择标准产品，再填写交易数据；用户不再手工输入产品名称、代码和行情代码。所有持仓界面只显示中文，并提升高 DPI 场景下的文字清晰度。

## 交互

1. 各资产页主操作统一为“增加一笔持仓”。
2. 弹窗顶部为产品搜索框，输入名称、代码或简称后延迟 250 毫秒查询。
3. 搜索结果显示“产品名称、标准代码、市场/类别、数据来源”；选择后锁定产品身份并自动填入行情代码、币种、交易市场和必要的报价元数据。
4. 已有持仓的加仓、减仓和编辑直接复用已选产品，不重复搜索。
5. 银行理财不调用搜索服务，保留名称、代码、机构等手动录入。

## 数据源

- 股票、基金、债券、贵金属、外汇、期货：东方财富证券搜索接口，并按资产类别严格过滤。
- 加密货币：币安现货交易对目录，只返回可交易产品。
- 银行理财：手动录入及 CSV 导入。
- 搜索服务统一返回 `symbol/name/exchange/quoteSymbol/currency/source/category/metadata`，前端不依赖上游原始字段。

## 概览

- 内部资产类型、动作和币种代码全部通过中文映射显示。
- “币种敞口”改为“币种分布（人民币折算）”，解释为各计价币种对应资产折算成人民币后的金额和占比。
- 仅展示实际持有且人民币市值大于零的资产类型和币种，避免空白英文枚举。
- 正文字号不低于 12px，关键数字不低于 21px，采用系统中文字体与等宽数字特性。

## 容错与测试

- 关键词不足 1 个字符时不请求；单次最多 20 条；15 秒超时。
- 上游失败返回可理解的中文错误，搜索结果为空时提供明确空状态。
- 后端使用 `httptest` 验证解析、过滤和中文映射；前端使用 Node 合同测试验证文案、搜索选择和无英文内部枚举。

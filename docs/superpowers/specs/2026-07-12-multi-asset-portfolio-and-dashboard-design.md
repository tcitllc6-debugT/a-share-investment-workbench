# 多资产持仓中心与总览优化设计规格

## 1. 目标

在不破坏现有股票自选、股票交易日志和 FIFO 持仓计算的前提下，完成以下能力：

1. 总览“今日关注”优先读取本地雷达快照，后台刷新，不阻塞首屏。
2. 删除股票自选页面的“全部分组”下拉框，保留左侧分组导航和单股分组管理。
3. 总览市场快讯混排财联社电报与新浪财经，按发布时间排序并去重。
4. 股票交易记录增加“加仓”和“卖出”快捷入口，生成新交易而不是修改历史交易。
5. 将持仓中心扩展为股票、基金/ETF、债券、贵金属、外汇、期货、加密货币和银行理财的统一持仓系统。
6. 形成对本地 16 个开源项目的功能吸收、数据源与许可证报告。

## 2. 明确边界

- 所有交易和持仓均由用户手工录入，不接券商、银行或交易所账户。
- 第一版不自动下单，但统一账本预留订单来源和外部流水标识。
- 股票、基金/ETF、债券、贵金属、外汇、期货和加密货币自动获取公开行情。
- 银行理财采用手工净值/估值和 CSV 导入，不承诺自动行情。
- 所有资产统一折算为人民币；界面同时保留原币金额、汇率、行情来源和更新时间。
- 应用首页的“持仓与自选”继续只展示股票；持仓中心的“持仓概览”汇总全部资产。
- 不把 AKShare、Qlib、vn.py、QUANTAXIS 等 Python 运行时打包进桌面应用。

## 3. 总览与自选改造

### 3.1 今日关注

当前总览直接调用网络异动接口，导致首屏等待。改造后数据流为：

1. 页面挂载后立即调用 `GetIntradayRadarSnapshot`。
2. 有缓存时直接显示前四条 P1/P2 信号和快照更新时间。
3. 无缓存时显示轻量空状态，不显示全局加载遮罩。
4. 后台触发一次 `RefreshIntradayRadar`，成功后替换快照。
5. 刷新失败时保留旧数据，并记录失败原因，不把列表清空。

### 3.2 股票自选

- 删除工具栏的分组下拉框及其空白占位。
- 搜索框、股票数量保持同一行并左对齐。
- 左侧导航仍负责切换全部自选和用户分组。
- “设置分组”继续处理一只股票属于多个分组的情况。

### 3.3 双源市场快讯

- 后端轻量查询支持来源集合，单次读取财联社电报和新浪财经。
- 排序优先使用 `publishedAt`，缺失时回退 `dataTime/time`。
- 以标准化标题/正文摘要和五分钟时间桶去重。
- 总览显示 8 条，保证同一来源最多连续出现 3 条。
- 每条显示来源标签；一个来源无数据时继续显示另一个来源。

## 4. 统一资产领域模型

### 4.1 `asset_instruments`

保存资产定义：

- `id`
- `asset_type`: `stock`, `fund`, `bond`, `precious_metal`, `forex`, `future`, `crypto`, `bank_product`
- `symbol`, `name`, `market`
- `currency`
- `unit_name`
- `contract_multiplier`
- `quote_provider`, `quote_symbol`
- `metadata_json`
- `created_at`, `updated_at`

### 4.2 `asset_transactions`

保存不可变交易账本：

- `id`, `instrument_id`
- `action`: `buy`, `sell`, `subscribe`, `redeem`, `interest`, `dividend`, `fee`, `transfer_in`, `transfer_out`, `valuation`
- `position_side`: `long`, `short`, `none`
- `quantity`, `unit_price`, `amount`, `fee`
- `currency`, `fx_rate_to_cny`
- `trade_time`, `settlement_date`
- `reason`, `notes`, `source`, `external_ref`
- `created_at`, `updated_at`

历史交易只能通过显式编辑修改；加仓和卖出永远创建新记录。

### 4.3 `asset_quotes`

- `instrument_id`, `price`, `currency`
- `quote_time`, `fetched_at`
- `provider`, `status`, `error_message`
- 每个标的只保留最新快照，并按日保存收盘快照供收益曲线使用。

### 4.4 `fx_rates`

- `base_currency`, `quote_currency`, `rate`
- `rate_time`, `fetched_at`, `provider`, `status`
- 持仓汇总统一使用兑人民币汇率；人民币汇率固定为 1。

### 4.5 `portfolio_snapshots`

每日保存总市值、投入成本、累计收益、浮动盈亏、已实现盈亏和分类占比，用于趋势和回撤分析。

## 5. 资产计算规则

### 5.1 股票与基金/ETF

- 数量和成本使用 FIFO 交易批次。
- 市值 = 剩余数量 × 最新价。
- 已实现盈亏由卖出批次匹配成本计算。

### 5.2 债券

- 支持面值、净价、应计利息、票面利率、付息频率和到期日。
- 市值 = 面值数量 ×（净价百分比 + 应计利息百分比）。
- 利息使用独立 `interest` 流水，不混入买卖价差。

### 5.3 贵金属

- 支持克、千克、盎司；入账时保存单位，计算前统一换算。
- 支持人民币和美元计价，美元报价通过汇率转人民币。

### 5.4 外汇

- 标的是货币而非货币对持仓。
- 市值 = 持有货币数量 × 该货币兑人民币汇率。
- 买卖差价、换汇手续费分别记录。

### 5.5 期货

- 支持多头、空头、合约乘数、开仓价、结算价、保证金比例和到期日。
- 浮动盈亏 = 方向符号 ×（结算价 - 开仓均价）× 手数 × 合约乘数。
- 占用保证金与名义市值分开显示，不与现货市值混淆。

### 5.6 加密货币

- 支持小数数量和交易对映射。
- 首选人民币报价；无人民币报价时用稳定币/美元报价再折算人民币。

### 5.7 银行理财

- 支持本金型和净值型产品。
- 净值型市值 = 份额 × 最新手工净值。
- 本金型使用手工当前估值或按确认收益入账。
- CSV 导入必须预览、校验并支持整批撤销。

## 6. 行情适配层

每类数据源实现统一接口：

```go
type QuoteProvider interface {
    Supports(instrument AssetInstrument) bool
    FetchQuotes(ctx context.Context, instruments []AssetInstrument) ([]AssetQuote, error)
}
```

推荐链路：

- 股票、基金：现有东方财富/新浪接口。
- 债券：中国银行间市场/东方财富公开行情，失败时手工价格。
- 贵金属：新浪/东方财富商品行情，外盘报价作为备用。
- 外汇：东方财富盘中汇率，Frankfurter/ECB 日参考汇率备用。
- 期货：国内交易所/新浪期货行情，东方财富备用。
- 加密货币：Binance 公共行情，CoinGecko 公共接口备用。
- 银行理财：手工净值和 CSV。

缓存策略：盘中行情 15-60 秒，外汇参考汇率 6 小时，收盘后行情固定到下一个交易日。所有适配器保存上次成功数据、来源、延迟和错误原因。

原“股票持仓”标题改为“金融产品持仓”；原“持仓概览与交易账本”改为“查看各类资产的市值、成本与收益”。

## 8. 加仓和卖出快捷链路

- `加仓`：复制标的身份，方向固定为买入，价格默认最新价，数量为空。
- `卖出`：复制标的身份，方向固定为卖出，价格默认最新价，显示可卖数量。
- 卖出数量不得超过 FIFO 剩余量。
- 保存后刷新交易列表、股票持仓、持仓概览和应用总览。
- 取消弹窗不产生任何记录。

## 9. 数据迁移

1. 启动前备份 SQLite 数据库。
2. 使用 schema 版本同步迁移。
3. 将现有 `trading_record` 股票记录映射到统一标的和交易表。
4. 保留旧表只读一个版本周期，提供回滚脚本。
5. 对迁移前后股票数量、FIFO 成本、已实现盈亏做逐项对账。

## 10. 测试与验收

- 总览首屏测试：本地快照先于网络刷新显示。
- 双源资讯测试：排序、去重、来源降级。
- 快捷交易测试：预填、超卖拦截、保存刷新。
- 各资产计算表驱动测试。
- 汇率缺失、行情过期和数据源失败测试。
- 数据迁移与回滚测试。
- 100%、150%、200%、300% DPI 布局测试。
- Windows Wails 构建；Mac 构建在 macOS CI/实体机完成。

# A-Share Desk Engineering Audit - 2026-07-10

## Scope

Review of the current independent A-Share Desk replica after the local K-line cache, multi-empty-line scanner, portable Windows distribution, signed updater, and high-DPI shell work.

## Fixed In This Pass

- First-run Windows windows no longer default to 50% of the logical screen. Saved dimensions remain intact when they fit and are clamped when they do not.
- The application shell reserves the bottom navigation height with `100dvh` instead of `92vh`.
- The multi-empty-line scanner uses a compact table at narrow logical widths and a shorter K-line dialog.
- A macOS universal-DMG GitHub Actions workflow exists for a real macOS runner.

## Findings

### Resolved - Managed updates use GitHub Releases

The application, release scripts, and GitHub Actions workflow now use this repository's HTTPS GitHub Releases channel. Legacy custom-server values are migrated to the repository default, while the signed manifest and SHA-256 asset checks remain enforced.

### P1 - Break the frontend entry bundle into feature chunks

Evidence: the current Vite production build reports one entry JavaScript chunk of about 6.17 MB before gzip, plus a warning for chunks over 500 KB.

The desktop app starts with many heavy views and charting/markdown dependencies in the same bundle. Use route-level `defineAsyncComponent`/dynamic imports for research, agent, prompt, fund, and K-line modules. Keep stock watchlist and market overview eager. Measure startup time and memory before and after.

### P1 - Restore unsuppressed frontend error visibility

Evidence: `frontend/src/App.vue`, `frontend/src/components/stock.vue`, and `frontend/src/components/settings.vue` each install `window.onerror` handlers that return `true`.

Returning `true` suppresses browser-level error reporting, and multiple global handlers replace each other depending on page load order. Install one handler in `frontend/src/main.js`, preserve the previous handler, emit structured diagnostics, and return `false` outside production debugging mode.

### P1 - Mac packaging pipeline needs a repository and signing credentials

Evidence: the local checkout has no Git remote; this Windows machine has no Xcode, `codesign`, or `hdiutil`.

The new workflow can build a universal DMG only after this independent project is pushed to a GitHub repository. Until `MACOS_SIGN_IDENTITY` and Apple notarization credentials are configured, the CI output is an unsigned test artifact and Gatekeeper will warn users.

### P2 - Continue replacing viewport-fixed component heights

Evidence: there are still 18 component uses of `calc(100vh - ...)`, including all-stock, fund ranking, research report, transaction log, and calendar views.

The app shell now reserves navigation correctly, but those components should use a shared `--app-content-height` CSS variable or a composable. Prioritize watchlist, transaction log, research center, and fund ranking, because they are most likely to be used on a 300% display.

### P2 - Add frontend interaction tests and screenshot checks

Evidence: frontend scripts currently provide only `dev`, `build`, and `preview`; there is no component-test runner. Existing checks for this pass are lightweight Node regression checks.

Add Vitest and Playwright. Cover compact/wide shell behavior, menu overflow, the multi-empty-line column set, K-line modal bounds, updater UI states, and the main screens at 640x360 / 1280x720 / 1440x900 logical viewports.

### P2 - Add operational health reporting for providers and updater

The news, quote, K-line, and updater paths have useful local behavior but no single diagnostic view for request latency, cache age, source status, retry count, or latest error. Add a read-only Settings diagnostics panel and redact all credentials.

### P3 - Consolidate duplicated presentation logic

Several views independently define fixed-width filters, tables, and viewport-height formulas. A small shared `ResponsiveDataTable` and `useAvailableHeight` composable would reduce future DPI regressions without forcing a wholesale UI rewrite.

## Recommended Next Order

1. Configure HTTPS for updates and release signing/notarization credentials.
2. Push this independent repository, trigger the macOS workflow, and validate the DMG on both Apple Silicon and Intel.
3. Migrate the four most-used fixed-height views to the shared content-height contract.
4. Split the frontend bundle and measure cold-start improvement.
5. Add Playwright visual regression coverage for high-DPI logical viewports.
